# Course requirement mapping

Source: the supplied five-page DBMS Level 3 Project Requirements.

| Requirement | Implemented evidence |
|---|---|
| Meaningful application beyond CRUD | Private claims, explainable matching, approval and atomic recovery |
| Two-member ownership | Team names/SRNs and component ownership in TEAM_CONTRIBUTIONS.md; personal review remains each student's responsibility |
| SQL plus NoSQL | PostgreSQL 17.6 and MongoDB 8.0.15 |
| ER/relational/document design | ER diagram, db/schema.sql, data dictionary and report |
| DDL CREATE/ALTER/DROP | Real schema/migration and disposable DDL examples in db/queries.sql |
| DML and advanced queries | Reports/claims CRUD, joins, GROUP BY/HAVING, ordering, aggregates, subqueries |
| At least four SQL advanced concepts | Transactions/locks, views, stored functions, triggers, partial/composite/GIN indexes, full-text search |
| NoSQL advanced concept | Strict validation, indexes, aggregation and idempotent event projection |
| Next.js interface | Report forms, flexible descriptors, search/filters, dashboards, matches, claims, staff and mobile views |
| API integration and environment configuration | Route handlers, services, pg/Mongo clients, .env.example |
| Two roles and authentication | Backend student/staff authorization, scrypt and expiring sessions |
| Database integrity | CHECK/FK/unique constraints, guard/deferred triggers and MongoDB JSON Schema |
| Soft-copy documentation | Final PDF, screenshots, diagrams, schema, queries, tests and presentation |
| Git/GitHub | Public repository and reproducible source; genuine individual commits/review to reflect actual work |
| Final demonstration | PRESENTATION_AND_VIVA.md and presentation speaker notes |
| Custom design | Specific ownership/recovery rules and relational/document separation |

Title uniqueness/approval and each student's personal viva performance are instructor/student responsibilities. Automated verification and real browser captures are complete for the supplied synthetic scenarios.
